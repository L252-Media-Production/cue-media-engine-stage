# CueME Stage: Design Notes and v0 Scope

Status: discussion draft, 2026-11-20. Owner: JC (L252 Media Production).

## Goal
One native macOS app that combines the ProPresenter / FreeShow content model (songs, lyrics, scripture, timers, stage displays) with the Resolume-style layered compositor and canvas (virtual screens mapped to physical outputs). Main reason: avoid running multiple computers for displays and remove the latency of the loops between them. Used first for L252, later shipped to others.

## Decisions so far
- Name: CueME Stage, a sibling of CueME (the audio cue player).
- Fully native: Swift, Metal, AVFoundation/VideoToolbox, CoreAudio. Apple Silicon only. Xcode project (generated by XcodeGen) with local Swift packages.
- Output engine runs as its own process, separate from the operator/editor UI. If the UI crashes or hangs, the outputs keep running. This is the main route to "never drops a frame". A hot standby instance is possible later.
- Reliability beats features: v0 does less but must not drop frames.
- **The app's own interface is the primary way to operate it.** Companion (module plus HTTP/OSC API, tablet as another Companion surface) is a secondary, equal-capability control path. WING/OSC is not required.
- Audio: video clips play their own embedded audio inside the app. Songs and music go through CueME (https://github.com/L252-Media-Production/cue-media-engine, Python/pygame, HTTP 8080, OSC 9000, existing Companion module). Long term CueME's engine becomes part of the app, so all audio sits behind one internal audio-output interface from day one.
- Import: ProPresenter library import is wanted. It should be usable first and look identical second. FreeShow data is also an import target.
- IMAG: one broadcast feed in for now, no video mixing in this version.
- NDI send and receive are part of the spike, after the SDI path works. NDI lets other Macs view the output without a card and gives a second live-source path.

## Hardware (known)
- Test Macs: M1 Pro MacBook Pro, M1 Max Mac Studio, base M5 Mac mini.
- Capture and output: 5 Blackmagic DeckLink Duo 2 cards (4 SDI connectors each, each set to in or out, up to 1080p60). Real use is 2 cards at a time, each Mac with one Sonnet Echo III Thunderbolt chassis (one chassis per Mac). Two Macs can be tested at the same time.
- Real setups typically use 2 stage displays (DSMs) over SDI.
- Largest possible canvas, not the current one: two 1080p projectors at the sides and two portrait TVs at centre stage, about 6000x1920. Downstage monitors are separate outputs, not part of the canvas.

## Architecture sketch
1. **Output engine (process A, `StageEngine`):** Metal compositor, layer stack (video/image background, text/slide layer, live-input layer), canvas with virtual screens mapped to outputs, per-output mapping, frame pacing against the output clock.
2. **Outputs:** everything the compositor sends frames to implements `OutputSink`. DeckLink SDI out (primary), NDI, and display outputs. Stage outputs render their own layouts (lyrics, timer, messages, next slide, clock).
3. **Inputs:** DeckLink SDI in (IMAG) as a live layer, NDI in later.
4. **Operator and editor UI (process B, `CueMEStage`):** the main way to run and prepare a service (see "UI priorities" below). Talks to the engine over local IPC.
5. **Control API:** HTTP/OSC plus a Companion module (actions, feedbacks, variables, presets). Every UI action is also an API action, so the UI and Companion cannot drift apart.
6. **Audio interface:** one internal audio-output abstraction. First implementation: in-app playback for video-clip audio. CueME is triggered externally over OSC/HTTP in v0.

## UI priorities
Because the app UI is the primary control surface, the operator view is part of v0, not a polish item. Order of importance:
1. **Operator (run) view:** show/playlist panel, the live slide, a live monitor per output screen, one-key go/next/previous, clear and blackout, status indicators (outputs, IMAG signal, CueME connection, dropped frames). The operator view does not show the next slide (no NEXT monitor or marker); the engine still computes it for stage displays and control surfaces.
2. **Slide and song content:** simple song/lyrics editor, scripture lookup, background assignment, per-song CueME track.
3. **Stage layouts:** pick and tweak a few ProPresenter-style layouts (lyrics, timer, messages, next slide).
4. **Output setup:** assign virtual screens and stage layouts to DeckLink connectors.
5. Later: full layout designer, template editor, canvas mapping UI, clip grid.

## Known constraints and open items
- **Portrait over SDI:** SDI frames are landscape. A portrait output must be rendered rotated into a 1920x1080 frame and rotated back by the display or a converter. Needs checking per display.
- **Connector budget:** 2 Duo 2 cards give 8 connectors, each either input or output. IMAG in (1) plus 2 stage displays (2) leaves 5 for the canvas, so the full 4-output canvas fits. Also check Echo III slot count and Thunderbolt bandwidth on each Mac.
- **A/V sync:** video with embedded audio plays in-app (one clock). Music via CueME is a separate process, so any cue that must stay locked to video needs a measured offset.
- **Display count on Apple Silicon:** base M-series chips drive few displays. SDI via DeckLink is the primary output path partly for this reason.
- **Two-Mac testing:** the second Mac can serve as a hot standby test, a remote operator view, or a second output node. Decide which when engine IPC is designed.
- **Speech to scripture (FreeShow feature):** on-device speech recognition feeding fuzzy match against Bible text. Make it suggest, then confirm, not auto-cue, on a live output.
- **ProPresenter import:** the format is protobuf-based and reverse-engineered by others; confirm the license and legal position before shipping.
- **SDK licences:** the DeckLink and NDI SDKs are build-time only and are not committed. Read both licences before shipping a distributed app. End users need Blackmagic Desktop Video for SDI.
- Resolume feature priority (clip grid, effects, BPM sync, pixel mapping, edge blend) to be decided later.

## v0 scope: one rehearsal-worthy service
- 3 to 4 songs, each with lyrics over a looping background video and a CueME track trigger.
- One IMAG feed from SDI as a layer or fullscreen cut.
- Bible verses (typed or picked); mic-to-verse comes later.
- Stage layouts for 2 SDI stage displays, ProPresenter-style: lyrics, timer, messages, next slide.
- A working operator view (UI priorities 1 to 3) plus Companion control for all of the above.
- Engine correctness and frame pacing come first; the editor itself stays simple.

## After v0
ProPresenter/FreeShow import, mic-to-scripture, effects and clip grid, full canvas mapping UI, edge blend, CueME audio engine merged in, failover instance, shipping to other users.

## Engine spike (first milestone)
Question: can this Mac hold a stable 1080p60 SDI output while compositing video and text in Metal?
1. Loop a background video, hardware-decoded, as a Metal texture.
2. Draw a text layer over it (a lyric line plus a clock so timing is visible).
3. Composite on the GPU into a 1920x1080 frame at 60 fps.
4. Send it out one DeckLink SDI connector, scheduled against the card's clock.
5. Log frame timing, late or dropped frames, and CPU and GPU load.
6. Then add NDI send and receive, a second SDI output, and the IMAG input.

Pass criteria: an hour or more with zero dropped frames on the Mac Studio, then repeat on the MacBook Pro and Mac mini.
